# 规则语料说明

> 本目录是**候选种子与回归网**，不是漏洞结论的判定依据。

## 定位

引擎的分层是：**规则/污点扫描产出候选 → LLM 与人工判定 → 机制固化**。

- 规则命中意味着"这里值得看一眼"，**不构成漏洞结论**；
- 所有扫描结果在 `scan` 的 `json` / `llm` 输出里逐条带
  `candidate: true` 与 `decision_required: true`，下游必须先复核再下结论；
- 判定完成后，值得固化的形态应沉淀为**引擎检测器或机制层判据**，而不是继续叠加规则。

## 冻结约定

1. **不再新增规则**：除非同时**替换**掉一条同类规则（净数量不增），或该规则来自一次
   真实误报/漏报的回归用例；
2. **只加回归用例**：新的漏报/误报应先变成测试（`cargo test` 或夹具用例），
   再由测试驱动修改既有规则；
3. **规则只做候选**：不得把"规则命中"当作可达性/数据流证据；
   需要证据的判定走污点分析与跨文件追踪；
4. **描述文案面向使用者**：写清"为什么存在这条判据"，不写内部编号、里程碑代号、
   被审计项目名或机器信息。

## 目录

| 路径 | 用途 |
|---|---|
| `*.yaml` | 模式规则（正则/结构匹配），产出候选 |
| `taint/` | 污点规则（source/sink/sanitizer 定义），参与数据流追踪 |
| `audit-packs/` | 审计证据包：按 CWE 组织的取证步骤与 TP/FP 判据，供判定流程引用 |

## 自定义规则

项目级规则放在 `<项目>/.ctx-audit/rules/`，优先级高于本目录（见 `docs/custom-rules.md`）。
